# 正文直接读取与续写

作者指令：“取消密钥这个动作，软件指令可以查看内容。”本书和空母版默认采用直接文件模式。阅读器选择章节即可阅读、复制和导出，不需要导入钥匙。GPT收到仓库链接和接管指令后，可直接读当前正文与记录。

## 当前正式来源

- `book/state.json`：书籍身份、真实采用进度、候选与修订历史、资料版本和全文回看覆盖。
- `book/workflow.json`：当前任务、阶段、下一项工作；不是后台写作进程。
- `book/chapters/`与`book/records/`：state引用的不可变正文和章后记忆，读取后核对哈希。
- `book/inputs/`：state引用的canon与roadmap；未来计划不等于已经发生。
- `book/接管记录.md`：当前事实与接续事项；有旧说明时，以最新state和本文件的现行存储规则为准。
- `online/index.json`：阅读器目录和进度，正文路径直接指向章节文件。`manuscript_storage=plain_files_v1`、`requires_reader_key=false`。

## GPT继续当前书

先读默认分支最新版本并核对预期分支头，再运行：

```bash
python3 tools/novel_state.py --root book status
python3 tools/novel_state.py --root book context --budget 40000 --out /临时目录/当前资料.md
```

实际阅读上一章全文、当前记录、设定与路线，再处理已授权任务。候选、repair、check-record、adopt和checkpoint均直接使用`--root book`，不再先解锁。采用新章后生成并校验索引：

```bash
python3 tools/online_state.py build-index
python3 tools/online_state.py validate-index
```

将关联正文、记录、state、workflow、接管记录和索引作为同次GitHub提交保存，非强制推进并回读验证。保留同一任务的真实修订计数和全部历史，不将存储切换当成重开新书、重写正文或清零回看。

## 历史与新书

历史`vault/`不再是本书现行来源，保留旧档案不会使当前章节重新上锁。实际密钥文件不会放入仓库或网页。不要因为旧聊天仍提钥匙就恢复该操作。

新书使用更新后的空初始化包和《启动新书.txt》，生成新book_id，先选平台、研究和选题，再逐章写作。直接保存采用稿即可，无须创建钥匙。同一阅读器添加新仓库链接可切换作品。

直接文件模式保留字数、哈希、记录、三轮修订和五章全文回看检查。公开GitHub中的正文可以被公开读取；网站访问权限与仓库可见性分别生效。
