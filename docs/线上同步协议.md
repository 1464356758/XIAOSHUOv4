# GitHub线上同步与阅读数据

仓库默认分支是本书唯一正式来源。`book/state.json`保存采用版本，`book/workflow.json`保存当前任务、平台和选题，`online/index.json`是网页可读索引；它们在同一次远程提交中保持一致。

默认直接文件模式，不需要阅读密钥。正文与记忆直接按state的路径读取；历史vault不参与当前索引。存储恢复必须保留书籍身份、采用哈希、修订历史与回看，不把旧基线写回现行state。

## 任务阶段

WAITING_PLATFORM→RESEARCH_PLATFORM／SCANNING_RANKINGS→WAITING_TOPIC→PLANNING→WRITING→REVIEWING／REVISING→SAVING；每5章和阶段结束进入CHECKPOINT，处理完恢复当前流程。重要未解决问题记BLOCKED；核心工具finish通过后才记COMPLETE。

阶段描述的是已保存的工作位置，不是后台进程的心跳。停止聊天不会自动继续写作；网页仍保留该位置与更新时间。

```bash
python3 tools/online_state.py task --phase WRITING --chapter 1 --detail "准备第1章正文" --next "完成本章并集中检查"
python3 tools/online_state.py build-index
python3 tools/online_state.py validate-index
```

任务开始、阶段变化、采用、回看、重要规划变更和中断前更新并提交。程序不自行提交远程，实际由当前GPT的GitHub工具或已授权git连接执行。没有成功远程提交的临时结果不能报告为线上完成。

## 提交边界

1. 读取当前默认分支头与base tree。
2. 准备本次产物，运行核心校验、build-index、validate-index。
3. 以原tree为基础，仅加入本次变化，创建新提交，parent为所读头。
4. 非强制更新分支，并校验expected head；遇到冲突读取新版本后合并。
5. 回读workflow与online/index；新增采用正文时回读正文和记录并核对哈希。

不要逐个覆盖文件后留一个混合进度给网页。使用GitHub Git Trees／Commits／Refs或一个git提交打包关联变化。保留历史版本，不删除此前采用文件。

## 阅读器

网页默认每60秒读取当前选中公开仓库的`HEAD/online/index.json`，后台标签页暂停轮询，回到前台可刷新。手动刷新立即请求。网络、GitHub缓存与提交传播可能延迟，因此不是毫秒级推送。

从公开raw文件读取，避免对REST接口高频轮询。章节使用不可变路径，读取后验证正文SHA-256，防止索引与正文混用。请求失败保留当前内容并提示同步失败；不会把失败当作零章或完成。

整本导出对索引快照中的每章核验，再生成带UTF-8 BOM的TXT；任一章失败不输出残缺文件。待重新核对未完成时阻止整本导出；单章可以阅读并显示警告。切换作品会取消旧读取和导出，避免把上本书放进当前视图。

网页只读取公开数据，不保存访问密钥、不直接写仓库、不调用模型。私有仓库需要另行提供经授权的服务端连接；当前未假装完成这项能力。

## 母版与下一本

运行`tools/make_init_package.py`生成`初始化系统包.zip`。包在根目录提供系统文件，排除本书state、workflow、正文、候选、研究、测试日志和作品身份。默认reader_url可共用，同一个网页添加新仓库即可。

复制到新仓库后，把新链接和启动指令发给GPT，bootstrap生成新身份。已初始化仓库不得用初始化包清空覆盖。新项目不需要重新部署阅读器。
