# 私密稿保存与继续写作

公开GitHub用于保存加密后的正式书稿，公开进度只含书名、章名、字数、哈希和任务。AES-256-GCM把正文、章后记录、核心state、候选历史和接管笔记一起加密，公开目录也参与认证。钥匙由安全随机数生成，不放入仓库或网站源码。

`book/private_storage.json`指向不可变的`vault/book_<密文哈希>.json`。这是当前正式书稿；原`book/state.json`保留为迁入前基线，核心工具会拒绝把它当最新书。未启用私密稿的空母版仍按原流程初始化。

## 作者阅读

网页先显示真实采用章数与目录。点击“导入私密阅读钥匙”，选择本书独立交付的JSON钥匙文件，然后即可阅读、复制、导出。钥匙仅保留在该网页内存，关闭或刷新网页需再次导入；不会写入网址、浏览器持久存储或发往GitHub。“锁定”清除本页钥匙与展示正文。已下载或复制的明文仍由作者自行保管。

网站本身继续维持原访问权限。加密不会删除已被公开提交过的内容，所以必须在第一次提交正文之前启用。已经公开的规划不会因此从历史中消失。平台接收和首发资格仍须按具体投稿通道核实，加密不是资格保证。

## GPT恢复当前书

1. 读取最新GitHub分支头，下载其`book/private_storage.json`与指向的密文，运行`python3 tools/private_book.py status`。不能只看旧聊天。
2. 从作者私密文件找本书“私密阅读钥匙”，实际文件名以本书接管记录为准；新书使用自己的钥匙，不能沿用其他书身份。缺钥匙时可以继续公开系统维护，不可编造已读正文。
3. 在公开项目之外建立一个新的工作目录：

```bash
python3 -m pip install -r requirements-private.txt
python3 tools/private_book.py unlock --key-file /私密路径/本书钥匙.json --out /私密路径/新的book目录
python3 tools/novel_state.py --root /私密路径/新的book目录 status
```

4. 所有正文恢复、context、candidate、repair、check-record、adopt、回看仍使用原核心工具，`--root`必须是刚解锁的私密目录。作者设定、路线和真实历史以该目录为准。不要用公开基线的设定替代其后修改。
5. `private_parent.json`绑定恢复时的密文版本。写前再次读取远程头；同revision内的新候选也不能被旧工作副本覆盖。若有新提交，先核对冲突，不能修改parent记录强行通过。
6. 更新公开workflow时仅写任务和统计，不贴正文、引文或包含剧情详情的检查结论。把工作流的新版本复制进私密工作目录，再封存：

```bash
python3 tools/private_book.py pack --source /私密路径/当前book目录 --key-file /私密路径/本书钥匙.json
python3 tools/online_state.py build-index
python3 tools/online_state.py validate-index
```

7. 将新密文、指针、公开workflow、索引作为同批更改提交，使用预期分支头、非强制推进。回读密文及指针，重新解锁核对实际章文与记录哈希后才报告已同步。私密工作目录和钥匙绝不提交。

## 新书第一次启用

空母版先正常选择平台、研究和规划。首次正文在公开项目之外的book副本创作。为本书生成一次钥匙，完整稿采用后封存；密钥文件与可下载正文交付到作者私密文件中。

```bash
python3 tools/private_book.py keygen --book-id 本书真实book_id --out /私密路径/本书钥匙.json
python3 tools/private_book.py pack --source /私密路径/本书book副本 --key-file /私密路径/本书钥匙.json
```

封存前后仍按原写作规程检查正文。公开索引校验只检查密文完整性、版本、身份和目录；没有钥匙不声称已验证正文语义。解锁会认证密文并核对实际state、正文和记录的哈希。该模式需要Python的cryptography依赖，浏览器使用WebCrypto和gzip解压；无须GPT API密钥，也不会在网页后台继续写作。
